# ASR contract

`vinpst-asr` owns the ASR backend/session contract. It keeps recognition behavior behind Rust trait boundaries while preserving the legacy daemon/frontend payload shape.

## Current crate responsibilities

`crates/vinpst-asr` is split by responsibility while keeping the public trait boundary stable:

- `traits.rs`: `AudioDeliveryMode`, `BackendCapabilities`, `BackendDescriptor`, `RecognitionContext`, `RecognitionEvent`, `RecognitionSession`, and `AsrBackend`;
- `error.rs`: `AsrError`;
- `mock.rs`: deterministic buffered/streaming/early-final `MockAsrBackend`;
- `command.rs`: command provider specs, JSON request/response types, legacy batch and streaming runners, process runner helpers, and `CommandAsrBackend`;
- `factory.rs`: config-selected backend factory and config-derived `AsrBackendState`;
- `sherpa/`: a public specification facade, offline model-layout/path inference, and the feature-gated official runtime backend;
- `payload.rs`: conversion from recognition events to the legacy recognition payload JSON model;
- `tests.rs`: behavior-preserving coverage for mock, command, factory, and payload contracts.

Command providers use legacy batch or `.streaming` runners through the factory, while the JSON helper seam remains available for explicit process-runner tests and small helper integrations. Local `sherpa-onnx` now has an explicit typed config seam, local model/hotwords path validation, offline SenseVoice layout inference, typed Qwen3 ASR metadata mapping, and an optional official runtime adapter behind the `sherpa-onnx-backend` Cargo feature. Default builds keep the runtime disabled so ordinary CI and command-demo installs do not download or link native ASR libraries. The validation seam accepts relative or absolute local model and hotwords paths, rejects empty values and URL-like paths, and verifies model directories plus regular hotwords files before any runtime is constructed.

The CLI preserves legacy command-provider script editing as `provider edit`/`provider e`; the former Rust-specific `provider edit-script` spelling remains accepted as a compatibility alias. Typed provider configuration uses the distinct `provider configure` command. Script editing resolves exact installed ids before explicit registry short ids, rejects local/remote providers, treats a path-like command as the first candidate and then scans arguments, opens only an existing regular file, and never mutates config. Editor selection is explicit `--editor`, `$VINPST_PROVIDER_EDITOR`, `$VISUAL`, `$EDITOR`, then `vi`; dry-run resolves the entire plan without launching a process.

## Daemon integration

`RuntimeState` owns a boxed `AsrBackend` and an active `RecognitionSession` while recording. The default daemon uses `MockAsrBackend`; explicit configured paths can build the active config-selected backend to exercise command ASR seams.

The current runtime flow preserves the upstream recording threshold and streaming event semantics:

```text
StartRecording
  -> create_session
  -> begin audio recorder
  -> while recording, emit non-empty PartialText and early FinalText as RecognitionPartial
StopRecording
  -> stop recorder and collect raw PCM
  -> if raw sample count < 8000: cancel session -> Idle -> return empty D-Bus payload
  -> otherwise enter Inferring
  -> apply deterministic audio processing
  -> push/flush PCM to the active ASR session
  -> drain already-pending ASR events
  -> finish session
  -> poll and merge final/stop-time events
  -> any Error event fails recognition rather than becoming committed text
  -> use the last FinalText as the raw recognition result when present
  -> if no Final/Error: keep an empty raw payload and skip text finishing
  -> otherwise enter Postprocessing and run text finishing
  -> suppress a stop-time RecognitionPartial that was already emitted live
  -> emit RecognitionResult -> Idle
```

Exactly 8000 raw signed-16 samples is sufficient to enter inference; shorter captures never invoke ASR finishing or scene text processing. The legacy `StopRecording` reply for that short-capture path is the empty string rather than an empty recognition JSON object, and no `RecognitionResult` is emitted. A long-enough capture whose ASR session completes without `FinalText` or `Error` is different: it is a successful empty recognition, skips text postprocessing, emits the empty recognition JSON payload, and transitions `recording -> inferring -> idle` without `postprocessing`. Streaming `FinalText` remains retained for stop-time payload construction even when it has already been projected through `RecognitionPartial` during recording. Stop-time `Error` events are fatal. Immediate live `Error` notification classification remains a separate D-Bus error-info parity item because upstream delegates that projection to `common/dbus/error_info.*`.

This is a contract seam, not full legacy runtime parity. The feature-gated `sherpa-onnx` backend covers buffered offline transducer, Dolphin, SenseVoice, Paraformer, Qwen3 ASR, and Moonshine v1 plus all five frozen-upstream online runtime families: transducer, Zipformer2 CTC, Paraformer, NeMo CTC, and T-One CTC. Additional frozen-upstream offline model layouts remain tracked by the separate model/layout parity audit. Offline transducer, online transducer, Dolphin, SenseVoice, Paraformer, Qwen3 ASR, Moonshine v1, and Zipformer2 CTC are proven with real registry-model WAV samples. ## Command ASR provider contracts

A command ASR provider is configured with `type = "command"`, a `command`, optional `args`, `env`, `model`, `hotwords_file`, and `timeout_ms`. Provider ids ending in `.streaming` select the legacy JSON-lines streaming protocol; other command providers use the buffered raw-PCM protocol. Registry entries additionally carry `stream`, and validation requires it to agree with the `.streaming` suffix.

Buffered command sessions collect PCM until `Finish`, write raw signed-16 little-endian bytes to the helper stdin, trim stdout as final text, emit `Completed` on finish/cancel, and treat repeated `Finish` as idempotent. The explicit little-endian encoding is wire-equivalent to frozen upstream on supported little-endian Linux targets. Non-zero exit, timeout, empty stdout, stdin failure, or supervisor failure is fail-closed and cannot become recognized text.

Streaming command sessions are genuinely incremental and keep one helper process alive across audio pushes. The first chunk is retained as pending; the next push sends the previous chunk as an `audio` JSON line with `commit=false`. Stop sends the final pending chunk with `commit=true`, then `{"type":"finish"}`, and closes stdin. The helper can therefore emit `partial`, `final`, or `final_timestamps` events while recording is still active. Duplicate partial text is suppressed, early final text is projected through `RecognitionPartial` immediately but retained for the eventual result, blank `error` events fall back to `failed.`, `closed` completes the session, and malformed JSON fails closed. Cancel best-effort sends `{"type":"cancel"}` before process-group cleanup. The daemon live poller explicitly polls the recognition session between audio pushes so asynchronously arriving helper output is not limited to synchronous `PushAudio` returns.

Vinpst deliberately keeps stronger supervision than the frozen C++ command backends. Batch and streaming helpers run in their own Unix process group, direct-child exit cleans descendants, and stdout/stderr are independently limited to 1 MiB. Streaming uses the upstream 10 second final-wait default when `timeout_ms` is absent; when a positive timeout is explicitly configured, Vinpst applies it to each pipe write and the final wait rather than as one deadline measured from helper spawn, so a legitimate long recording is not killed solely because its duration exceeds the provider timeout. Frozen upstream streaming ignores provider `timeout_ms`, has unbounded recording-stage pipe waits, and has no output cap. Existing Vinpst one-shot batch/JSON behavior keeps an omitted timeout as no configured deadline (managed registry providers materialize 60 seconds) instead of copying frozen upstream's integer-zero batch timeout edge case.

`CommandAsrRequest` remains the internal buffered request type for batch/JSON runners and focused test seams. It carries provider metadata, recognition context, PCM layout, and interleaved signed 16-bit samples. The former one-shot JSON-lines streaming runner is test-only; production `.streaming` providers use the incremental session backend.

A JSON helper can return final text and optionally partial text:

```json
{"partial_text":"listening","text":"final text"}
```

A helper can also return an ASR-level error without a non-zero process exit:

```json
{"error":"asr failed"}
```

The deprecated `failure` response key is accepted as an alias for `error`. Non-zero exits, invalid JSON, missing final text, timeout, output-read, and output-limit paths are surfaced as backend errors. Overflow diagnostics identify stdout or stderr and the 1 MiB limit without including captured helper output.

The repository also ships `scripts/fixtures/command-asr-wav-helper.py` for external ASR CLIs that consume WAV files rather than the raw legacy PCM or vinpst JSON request directly. The helper reads `CommandAsrRequest` JSON from stdin, writes the request PCM as a temporary WAV file, exposes that path as `VINPST_ASR_WAV`, runs the command after `--`, and emits `{"text":...}` from trimmed stdout or `{"error":...}` for helper-level failures. It also exports `VINPST_ASR_PROVIDER_ID`, `VINPST_ASR_MODEL_ID`, `VINPST_ASR_HOTWORDS_FILE`, `VINPST_ASR_SAMPLE_RATE_HZ`, and `VINPST_ASR_CHANNELS` for wrapper scripts. This keeps real command-ASR integration usable with tools such as whisper.cpp or sherpa CLIs without adding a hard runtime dependency.

For user-level live trials, `VINPST_USER_PROFILE=real-command-asr-wav scripts/install/install-user-ime.sh` installs the WAV helper next to the daemon, generates a `real-command-asr-wav.json` config, and routes live PipeWire capture through the helper to `VINPST_USER_COMMAND_ASR_WAV_COMMAND`. That profile is an interim real command-ASR path: `vinpst doctor --config ...` should report a ready effective command backend, but this does not make the local `sherpa-onnx` runtime complete.


## Remote ASR provider contract

A remote ASR provider is configured with `type = "remote"`, an `endpoint`, a typed `model` or legacy `env.VINPST_ASR_MODEL`, optional `timeout_ms`, and optional environment values `VINPST_ASR_API_KEY`, `VINPST_ASR_LANGUAGE`, and `VINPST_ASR_PROMPT`.

The runtime uses an OpenAI-compatible buffered transcription contract:

1. `endpoint` may be a base URL or a full `/audio/transcriptions` URL; only `http` and `https` are accepted, and a bad scheme fails during prepare-before-swap before replacing the current backend;
2. signed interleaved PCM is encoded in memory as canonical 16-bit little-endian RIFF/WAVE and sent as multipart field `file` with filename `audio.wav`, alongside `model` and optional `language` and `prompt` fields;
3. a non-empty API key is sent as `Authorization: Bearer ...`, but backend/request debug output hides the key and prompt. Diagnostic URLs remove userinfo/fragments and replace query values with `REDACTED` while the real multipart request keeps the original URL, query values, prompt, and headers;
4. successful responses must be JSON objects with a non-empty string `text`; the backend is final-only and emits no invented streaming partials;
5. the configured endpoint is the only request target: redirects are disabled, so any 3xx is handled as an ordinary provider HTTP failure and its `Location` is never contacted. `timeout_ms` is enforced across the HTTP request and response body; pre-header and post-header stalls have distinct diagnostics. Success and error bodies are read as UTF-8 with a shared 1 MiB limit before JSON parsing or diagnostic-body rendering; oversized bodies and invalid UTF-8 fail with fixed messages that contain neither body content nor a raw URL. Non-success bodies within the limit retain their diagnostic text after replacing exact occurrences of the configured API key and prompt with `<redacted>`; this known-value replacement is not arbitrary secret detection. The current reqwest feature set does not enable compressed-response decoding, so the limit applies to the body bytes exposed by the transport reader. Warmup only creates and cancels a session without contacting the endpoint;
6. `GetAsrBackendState` and `runtime-status.asr.remote_endpoints` expose the configured ASR target independently from the separate remote-text server diagnostics, but only through the shared diagnostic URL representation: host and path remain visible, userinfo/fragment are removed, and query values are redacted.

`scripts/tests/asr/run-openai-compatible-asr-fixture-smoke.sh` deterministically validates multipart parsing, Bearer authentication, WAV shape/signal, model/language/prompt matching, response handling, and evidence redaction. `scripts/tests/asr/run-openai-compatible-asr-network-smoke.sh` separately runs the production daemon through proxy, bypass, HTTP failure, timeout, TLS trust, DNS, and refused-connection cases with redacted retained evidence. `scripts/live/niri/run-ime-fcitx-remote-asr-live.sh` proves the real Fcitx/PipeWire path against the independent loopback process and restores the original streaming backend. These fixtures prove protocol and local network semantics, not a third-party hosted service or production credential operations.

## Native `sherpa-onnx` backend contract

An empty `asr.active_provider` is a valid unselected/disabled configuration state, not a backend-load failure. Startup and reload expose no effective backend and no reload error; attempting to start a new recording then fails with a stable backend-not-ready error. If a provider is unselected while a recording is already active, the existing recognition session remains valid for that recording, but future sessions are disabled.

Reload preparation preserves the upstream create-session/cancel warmup boundary before publication. Vinpst deliberately tightens concurrency around it: configured backend preparation/application waits for `Idle`, and generation ids discard stale prepared backends or failures after a newer request supersedes them. Vinpst also deliberately re-prepares on explicit reload rather than copying the upstream `BuildRuntimeSignature` no-op optimization; the frozen upstream signature omits some runtime-relevant VAD parameters. `--no-asr` remains a stronger process-level policy than an unselected config and cannot be undone by later config reloads.

The bundled/default local provider id is `sherpa-onnx`, but it is not a runtime type discriminator. Any validated `type = "local"` provider id uses the same native Sherpa model-metadata path, matching upstream local-provider dispatch. In `vinpst-model.json`, `backend` is authoritative: missing/empty defaults to offline, `sherpa-offline` selects buffered offline recognition, `sherpa-streaming` selects online/streaming recognition, and any other non-empty backend is rejected. The descriptive `runtime` field may document the model but does not override `backend`.

The native backend uses the official `sherpa-onnx` Rust crate only when built with `sherpa-onnx-backend`. SenseVoice-style offline recognition accepts `vinpst-model.json` metadata and keeps directory inference as a compatibility fallback: the configured model directory must contain `model.int8.onnx` or `model.onnx`, plus `tokens.txt`. Offline transducer requires typed encoder, decoder, joiner, and tokens assets; Dolphin and Paraformer require typed model and tokens assets. Shared offline metadata forwards feature shape, threads, provider/debug flags, model type/modeling unit/BPE vocabulary, language-model settings, decoding method, active paths, hotwords, rule FST/FAR, blank penalty, and homophone-replacer files into `OfflineRecognizerConfig`. Qwen3 ASR requires typed metadata for its convolution frontend, encoder, decoder, tokenizer, and generation parameters; all declared assets are resolved under the model directory and validated before recognizer construction. Relative model paths are resolved under `VINPST_SHERPA_MODEL_ROOT` when the feature is active; user install profiles generate absolute model paths to avoid environment-sensitive activation failures.

Native PCM conversion uses the frozen-upstream `sample / 32768.0` normalization. Offline recognition remains buffered: the daemon collects PCM, then `SherpaOnnxRecognitionSession` runs optional VAD and `OfflineRecognizer::decode`. Non-empty `text` is preferred; when it is blank, concatenated `tokens` are used. Empty recognizer output is a normal completed recognition with no text. Native online sessions use the same result fallback, emit changed partials while decoding, preserve changed endpoint hypotheses before stream reset, and at stop emit a changed final hypothesis as `PartialText` before `FinalText`. Repeated `Finish` and `Cancel` are idempotent completion operations like upstream. Model hotwords are used only when metadata declares `supports_hotwords`; provider hotwords override model hotwords and force `modified_beam_search`. Missing offline thread metadata defaults to 4, while online runtime uses the upstream fixed runtime default of 4 threads. In-memory `tokens_buf`/`hotwords_buf` metadata remains an explicit model-metadata gap even though the Rust binding can represent it. The official native API is synchronous and exposes no safe cancellation handle, so a configured native `timeout_ms` is diagnostic-only rather than a fake deadline implemented by leaking a detached decode thread. Command ASR providers remain genuinely cancellable and use the shared supervisor to kill the helper process group on timeout, bound both output streams, and clean descendants after direct-child exit. `vinpst doctor` reports `not_configured`, `enforced`, or `unsupported` together with the configured value and an actionable reason.

## Diagnostics

The CLI diagnostics `vinpst doctor`, `vinpst asr-state`, and `vinpst audio-devices` resolve configuration consistently: an explicit `--config` path wins, otherwise an existing Vinpst XDG user config is used, and only a missing user config falls back to the bundled default. `doctor` keeps returning a structured report when setup is incomplete; its top-level `ok` reflects whether the active ASR backend can be constructed and prepared, with `status` set to `ready` or `setup-required`.

Both `vinpst-cli asr-state` and `vinpst-daemon asr-state` serialize `AsrBackendState` from config only. They do not reload or mutate the runtime backend. Remote endpoint entries use the shared redacted URL representation, so an endpoint can remain identifiable without exposing URL credentials, fragment data, or query values. The daemon diagnostic remains usable with `--configured-backends` even when the selected runtime backend is unavailable. A configured daemon using the normal recorder path also remains reachable with an unavailable-backend placeholder when initial ASR construction fails, allowing a later reload after model/provider repair. An empty active provider is the explicit legacy-compatible unselected state and reports `no active ASR provider is configured`; no fallback provider is selected implicitly.

## Known compatibility gaps

These gaps remain after the behavior-preserving ASR split:

- Native `sherpa-onnx` is feature-gated and supports offline transducer/Dolphin/SenseVoice/Paraformer/Qwen3 ASR/Moonshine v1 plus online transducer/Zipformer2 CTC layouts. Offline transducer, Dolphin, SenseVoice, Paraformer, Qwen3 ASR, and Moonshine v1 pass real WAV smokes with offline Silero VAD active; online transducer and Zipformer2 CTC pass real WAV smokes with the 200 ms recognizer warmup. Legacy endpoint rule defaults and metadata overrides are forwarded to the official runtime. Timeout capability is explicit: command helpers enforce configured deadlines across stdin/execution/output recovery, while native synchronous decode reports configured values as unsupported/diagnostic-only. Command helpers additionally have independent 1 MiB stdout/stderr limits and whole-process-group cleanup. Prepare-before-swap warm reload and the single non-blocking reload worker are implemented. Current cached-registry families are covered; broader legacy sherpa families remain incomplete.
- Offline Silero VAD resolves `VINPST_SHERPA_VAD_MODEL`, user/system XDG data paths, or the development asset; a missing or unloadable model degrades to untrimmed recognition. The native user-install profile installs the tracked MIT-licensed model under `fcitx-vinpst/vad`. `vinpst doctor` reports whether VAD is disabled, ready, or missing, including the resolved/requested path, source classification, strict parameter values, offline-only scope, and a repair hint for missing assets.
- The daemon routes recorder callbacks to chunked ASR sessions in legacy-compatible 800-frame batches. Callback-polled partials are emitted through D-Bus while recording; generation cancellation isolates recordings, and final/completed events remain available for stop processing. The opt-in virtual-source gate proves this path through non-silent isolated PipeWire capture and a real Fcitx client input context without physical audio devices.
- The D-Bus facade emits deduplicated `RecognitionPartial` D-Bus signals during recording through a generation-scoped 40 ms poller. Stop cancels the poller and suppresses a duplicate final partial.
- The retained frontend has a Fcitx D-Bus monitor for `StatusChanged(s)` and `RecognitionPartial(s)`. The monitor can be created before the daemon owns its well-known name and follows owner replacement without trusting arbitrary senders. For addon-owned sessions, partial text takes precedence over localized recording/commanding/recognizing fallback in the active input-context preedit. A temporary-HOME native online-transducer smoke proves that this partial reaches a concrete Fcitx test `InputContext` before stop, while `scripts/live/niri/run-ime-fcitx-virtual-source-live.sh` proves partial input-panel updates and final synchronous-stop commit in a real Fcitx client through isolated audio injection. Idle/error status clears frontend state. Representative GUI-toolkit rendering remains separate live work.
- Command and remote ASR providers are runtime-wired. Remote providers are buffered/final-only OpenAI-compatible HTTP clients; loopback multipart/Bearer recognition and prepare-failure preservation are live-proven. Deterministic process tests cover plain-HTTP proxy routing, proxy-URL Basic authentication for direct HTTP over plain-HTTP proxies and CONNECT through both plain-HTTP and TLS-protected HTTPS proxy endpoints, `NO_PROXY`, an additional PEM root from `SSL_CERT_FILE`, retained built-in `WebPKI` verification, one local CA-signed TLS interception relay with no retained plaintext, same-daemon atomic replacement of one CA-file path with mismatch rejection and idle recovery, 429/503, fail-closed 3xx handling with an untouched redirect target, request and response-body timeouts, untrusted self-signed TLS rejection, DNS failure, connection refusal, and credential redaction. Real hosted-provider, PAC, NTLM/Kerberos, enterprise TLS-interception policy and certificate deployment, and provider credential lifecycle plus production CA distribution/revocation operations remain unproven.

# Rust GUI contract

`vinpst-gui` is the standalone Rust management application. It replaces the legacy Qt/C++ management application without expanding the retained C++ boundary beyond the thin Fcitx addon.

## Implemented baseline

The first Iced 0.14 implementation is part of the workspace and provides four legacy-aligned top-level pages. Its global navigation opens the loaded config through a shell-free native or Flatpak host desktop-opener command. At startup it also checks the current upstream notification feed without blocking page or daemon initialization, shows only a newer validated notification, and preserves the legacy Details/OK acknowledgement lifecycle:

- **Control** shows daemon status, starts the daemon through D-Bus activation, stops/restarts the user service through shared typed direct-argv controls, confirms lifecycle results through a non-activating owner query, starts/stops normal recording, and edits the active scene/provider, capture target, language, VAD, and output-ducking settings. Its language and capture-device text fields submit a dirty, non-busy form through native Enter handling; clean submission remains a no-op and cannot bypass the normal save guards.
- **Resources** lists and filters typed ASR providers and scenes, adds custom Local, Command, and Remote ASR providers, edits configured providers through shared kind-specific typed forms, removes inactive user-defined providers through config-only persistence while registry-managed commands retain script cleanup, creates and edits validated scene definitions, binds scenes only to configured LLM providers through a typed selector with an explicit no-provider choice, selects the active scene, removes only inactive scenes, separates installed ASR models from a localized browsable live-registry catalog, filters available models by user-visible metadata, shows model type/language/declared size/hotword support/install status, installs or updates supported entries without requiring a typed registry id, removes inactive managed model directories, and exposes selectable secret-safe model/provider detail panels.
- **LLM** lists providers with redacted endpoints, adds and edits typed OpenAI-compatible provider definitions through secure API-key inputs, removes only providers whose deletion leaves the full config valid, tests configured providers through the shared production text adapter on a blocking worker while reporting only a candidate count, lists command adapters without exposing API keys, adds custom adapters and edits configured adapters through shared typed id/command/arguments/environment/working-directory forms, keeps ids editable only during creation, validates ids through the shared daemon runtime-path rule, removes user-defined adapters through config-only persistence while registry-managed adapters retain script cleanup, reads typed adapter running/PID state, starts and stops configured adapters over D-Bus with owner-generation-scoped post-action confirmation and a forced current-owner refresh that replaces earlier in-flight queries, and exposes selectable provider/adapter details built only from redacted typed summaries and configuration counts.
- **Hotwords** selects only configured local or command ASR providers, offers an asynchronous XDG Desktop Portal file chooser that fills only the path draft, sets or clears each provider's `hotwords_file` through full-config validation and conflict-aware atomic persistence, resolves a relative Local hotword path only when the provider model path is absolute, rejects relative model-plus-hotword combinations whose target depends on the daemon process environment, requires an absolute command-provider path for GUI content editing, and loads, edits, and saves UTF-8 content with a 1 MiB limit, regular-file and symlink checks, external-change detection, version-checked same-directory recovery hard links and atomic exchange that keep the configured path continuously available, exact mode and owner/group checks, fail-closed refusal for xattr or ACL metadata the GUI cannot safely preserve, adjacent recovery preservation of the previous file version, fail-closed refusal when the target is externally rewritten or recreated, a no-rollback policy after publication, saved-but-unconfirmed reporting for post-publication directory-sync failures, bounded final-state confirmation for active-provider reloads, an explicit activation-retry action that survives config refresh only while the persisted provider, target, and exact file version still validate and retries without rewriting the file, and post-reload config-target revalidation so background preparation failures or superseding config changes preserve the file but are reported as not applied, stale-result rejection, redacted diagnostics, and unsaved-change guards.

The application reads `VinpstConfig` directly, validates an explicit or discovered user config, and falls back to the bundled default only when the user file is absent. Its typed presentation locale follows `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, then `LANG`, normalizes legacy locale names, and currently provides English fallback plus zh_CN for the window title, navigation, Control page, daemon/recording lifecycle, desktop actions, startup-notification actions, the complete Hotwords interaction surface, Resources/LLM page chrome and row actions, localized installed-model titles and registry-catalog metadata, text-adapter runtime states, selectable model/provider/adapter detail projections, scene list/editor actions and provider choices, custom ASR provider forms plus fixed scene/provider mutation outcomes, LLM provider lists/forms/connectivity controls and candidate-count results, text-adapter forms plus fixed provider/adapter mutation outcomes, model and script install/progress/cancellation/retry panels, published-script recovery, managed-removal outcomes, adapter lifecycle confirmations, provider-script editing, and fixed configuration/resource mutation receipts. Non-recovery operation, model-install, and script-install failures render in a top-level modal overlay instead of entering the page layout; the modal blocks underlying controls, supports OK/Escape dismissal, and retains Retry when the failed workflow owns an exact retry request. Published-script recovery remains an explicit structured recovery panel because it carries config-only recovery actions. Machine-readable page ids, configuration values, protocol names, and raw lower-layer diagnostics remain locale-independent. GUI and CLI config mutations share the `vinpst-config` persistence API: validation precedes any filesystem mutation, an existing file receives an adjacent `.bak`, the replacement is written and synchronized beside the destination, and rename publishes it atomically. On Unix, both the replacement temporary file and any adjacent backup are created or tightened to mode 0600 before publication because typed configuration can contain API keys and provider/adapter environment values. The GUI refuses to overwrite a file changed after loading and refuses a save while a reachable daemon is non-idle or reports an active session. A missing daemon does not block an otherwise valid offline config save; the result explicitly reports that reload was skipped.

Daemon state and actions use the shared `vinpst-protocol` D-Bus constants, typed zbus calls, and `vinpst-daemon-control` user-service commands. Desktop file and notification-detail opening use direct argv (`xdg-open` natively or `flatpak-spawn --host xdg-open` when sandboxed), suppress child output, reap the launcher, and keep targets out of generic diagnostics. The Hotwords picker never commits configuration or loads content implicitly; the selected path must still pass the existing explicit Set path transaction before it becomes configured. Startup notifications use the shared no-redirect HTTP client, a five-second request deadline, the existing 1 MiB UTF-8 response bound, current upstream numeric `id` plus localized `title`/`text` fields, exact-locale/language/English/first-value fallback, and credential-free HTTPS-only Details URLs. Fetch, parse, and trust failures remain silent. A notification is marked read only after OK or Details, using a monotonic single-ID file at the legacy-compatible `$XDG_CACHE_HOME/fcitx-vinpst/read_notifications` path with bounded no-follow reads, symlink/non-regular refusal, mode-0600 temporary publication, file sync, atomic rename, and parent-directory sync. Status/save guards require `GetStatus` and `GetRuntimeStatus`, while `GetTextAdapterState` is optional adapter diagnostics; save requests `ReloadAsrBackend`; recording controls use `StartRecording`/`StopRecording`; and adapter lifecycle uses `StartAdapter`/`StopAdapter` with an immediate typed state refresh; the GUI does not parse CLI output or launch the CLI as a helper. A long-lived async zbus subscription installs a service-name-filtered `NameOwnerChanged` match before sampling `NameHasOwner`, so owner loss and recovery reconcile immediately without activating a missing service. Every daemon snapshot and fallback query carries an operation generation; owner transitions invalidate older generations so stale snapshots cannot restore a departed owner. If the signal stream is unavailable, the GUI reports degraded monitoring, reconnects the stream, performs one immediate non-activating query, and enables a serialized 30-second non-activating fallback only while degraded. Model installation runs in a dedicated blocking worker and uses the shared registry fetch/checksum/safe-extraction/atomic-materialization APIs. The Resources page reports catalog, byte download, checksum, extraction, metadata, and publication phases; a typed cancel control is observed during archive download, extraction, and cross-filesystem publication. Cancelling removes temporary download/extraction/publication state, preserves an existing installed model, rejects stale worker completions by operation generation, and retains the exact selector for retry. ASR provider forms keep ids and kinds editable only during custom creation, preserve them during edit, preserve `hotwords_file` and fields outside the active form, parse command arguments as typed JSON strings, expose environment keys with secure per-value inputs and typed map reconstruction, keep command/environment values and credential-bearing endpoints out of generic diagnostics, reject duplicate or stale provider snapshots, and save only after complete config validation. Configured text-adapter forms keep ids and forward-compatible fields immutable, parse arguments and environment as typed JSON string collections, edit command and optional working directory, keep process configuration out of generic diagnostics, reject stale adapter snapshots, block conflicting runtime/resource operations while dirty, and save only after complete config validation. Command ASR provider and text-adapter installs use the same owned worker state: the GUI first resolves a full or short registry id into a typed installation plan, refuses to replace user-defined entries, and collects every registry-declared environment value in secure inputs before any script download. Required values block confirmation while optional values may remain empty. Managed updates prefill existing declared values, allow explicit replacement, and preserve unrelated environment entries. The confirmed transaction publishes the executable script under the managed data root, validates and atomically saves the resulting typed config, and requests daemon reload. If publication succeeds but config persistence fails, the GUI keeps a typed recovery state with the published path and error, blocks conflicting resource operations, and offers config reload, config-only retry, or explicit dismissal that keeps the script. Recovery revalidates the current config, registry environment contract, and existing regular-file path and never downloads the script again. Exact managed command-provider rows also expose an Edit script action. The GUI launches the same shared typed provider-script plan used by the CLI, preserves the legacy explicit/`VINPST_PROVIDER_EDITOR`/`VISUAL`/`EDITOR`/`vi` priority, executes direct argv without a shell, and verifies that the resolved existing regular file is exactly the managed path before opening it. Cancellation is cooperative through script download; once configuration commit begins the UI enters a non-cancellable finishing state so a published script is not intentionally left without its config reference. Dropping any active GUI install operation, including application shutdown, requests cooperative cancellation rather than orphaning the worker. GUI and CLI model deletion share one typed managed-root boundary that rejects the root itself, paths outside it, non-directories, and active configured local-model paths.

`vinpst-gui --check --offline` produces a redacted machine-readable snapshot without opening a window or requiring a session bus. Packaging uses this mode to verify the installed binary, typed config loading, page inventory, and secret-safe diagnostics. `--check` without `--offline` additionally probes the live daemon.

The checked Arch, Debian, RPM, and Nix package paths install the GUI binary, desktop entry, and hicolor icons. This is a runnable product baseline, but it is not yet full legacy GUI parity.

## Boundary rules

- Keep GUI code in Rust. Do not port or retain the legacy Qt/C++ GUI as a product component.
- Keep the existing C++ code limited to the thin Fcitx addon boundary.
- Reuse typed config, registry, protocol, and diagnostic APIs. Runtime operations must use D-Bus or shared Rust libraries, not parsed CLI text.
- Never display API keys, authorization headers, raw prompts, or unredacted provider credentials.
- Config mutations must use the same validation, atomic-write, backup, and active-session guards as the CLI/daemon paths.
- Long-running resource operations must expose progress, cancellation, and a final typed result; closing the window must not orphan helper processes.

## Toolkit choice

Iced 0.14 is the current implementation toolkit. The application uses its typed state/message/update/view model, asynchronous tasks, native Wayland/X11 backends, and software renderer. Its text input/editor widgets expose focus traversal, standard clipboard editing, and Wayland/X11 input-method preedit/commit. Because the built-in buttons, checkboxes, pick lists, and sliders do not participate in the generic focus operation, the GUI enables Iced's bounded custom-widget API and wraps every enabled action/value control with one shared focus state and visible focus ring: buttons and checkboxes activate through Enter/Space, while selectors and sliders publish bounded previous/next typed values through the arrow keys without changing their existing pointer/overlay behavior. The current Iced 0.14 dependency graph and upstream main branch still have no AccessKit integration or stable accessibility-tree API; upstream accessibility issue #552 remains open. An application-local AccessKit bridge is therefore rejected for now because the toolkit does not expose a durable widget identity/tree lifecycle or platform accessibility event boundary that the GUI could implement safely. `gtk4-rs` remains the fallback because GTK4 provides native roles, properties, relations, states, and assistive-technology tree integration, but switching now would replace the complete view/widget layer rather than form a bounded slice.

The `0.1.0` support policy is therefore explicit: complete keyboard operation is supported, while screen-reader navigation and a platform assistive-technology semantic tree are unsupported. Every ordinary management and diagnostic task has a `vinpst` CLI path; frontend-only trigger keys and trigger mode remain available through `fcitx5-configtool`. The headless capability snapshot reports this policy and the CLI, Fcitx form, terminal configuration-file, and reload fallbacks without opening a window. Revisit semantic-tree support when Iced provides a stable platform tree/event boundary or when a deliberate toolkit switch is approved; do not add an application-local parallel widget tree.

## Remaining work

No ordinary upstream management task is known to be missing from the Rust GUI or its documented CLI/Fcitx fallbacks. Deterministic coverage plus the retained representative desktop paths are sufficient for the 0.1.0 management surface; additional per-mutation GUI live collectors are explicitly non-blocking.

Post-0.1.0 work is:

1. refine resource-specific error titles and recovery actions when concrete user reports expose an unclear outcome;
2. revisit assistive-technology semantic-tree support only through a toolkit-supported bridge or an approved toolkit switch;
3. add startup/package-size measurements and stable-layout visual regression coverage when those become product priorities.

Command-mode selected-text acquisition remains owned by the retained Fcitx frontend, where it is already implemented and live-proven. The legacy standalone Qt management GUI exposed no command-recording or selection action, so duplicating that frontend behavior in `vinpst-gui` is not a parity requirement.

Documentation may describe the GUI as the supported 0.1.0 management application, but must continue to state that screen-reader navigation and a platform semantic tree are unsupported.

## Testing rules

- Test state transitions, typed request construction, D-Bus behavior, redaction, config validation, and rendered user outcomes.
- Keep a display-independent check that packaging can run without D-Bus.
- Do not add tests that assert source declarations, widget implementation names, exact documentation wording, docstrings, or toolkit-generated source text.
- Keep screenshot tests limited to stable user-visible layout regressions; do not use them as substitutes for interaction tests.
